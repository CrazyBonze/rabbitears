# Rabbit Ears — Project Scope

> A dumb, kid-safe "cable box" built from a Dell Wyse 3040. Folders on a USB
> drive become TV channels that are always "on the air." You can't pick a show,
> only a channel. No internet content, no menus to get lost in, no apps.

This document is the source of truth for **what we're building, what we're not,
and how the repo and boxes are laid out.** If a feature isn't in here, it's
out of scope until this file says otherwise.

---

## 1. Goals and non-goals

### Goals
1. **Feels like real TV.** Channels play continuously on a clock-based schedule.
   Flip to channel 4 at 3:47pm and you land mid-episode, wherever it "would be."
2. **Zero-interaction recovery.** Power on, pull the plug, yank the USB: the box
   always comes back to a playing channel or a clear "NO SIGNAL" screen, never a
   shell, desktop, or error dialog.
3. **Kid-proof by construction.** The only reachable states are "channel N is
   playing," "standby," and "info overlay." There's nothing else to navigate to.
4. **Reproducible.** Either Wyse 3040 can be rebuilt to an identical state from
   this repo plus one Alpine `lbu` overlay file.
5. **Content is just files.** Adding a show means copying files into a folder.

### Non-goals (explicitly out of scope)
- Streaming services, YouTube, web browsing, or any internet video
- Kodi, a desktop environment, X11, or Wayland
- On-demand browsing ("pick an episode")
- Recording, DVR, pause/rewind
- Number-key channel entry (the remote has no number keys)
- Gyro/air-mouse support
- Commercials, AI-picked ad breaks, or MiniLM indexing (parked; see §9)

## 3. Platform: Alpine Linux, diskless + lbu

- **OS:** Alpine Linux (latest stable, x86_64), **diskless mode** booted from
  the internal eMMC.
- **Persistence:** `lbu commit` writes the system state (`/etc`, the world
  package list, and included paths) to an `apkovl` on the eMMC boot partition.
- **Package cache:** `setup-apkcache` on the eMMC, so packages reinstall offline
  at boot.
- **Init:** OpenRC. No systemd, so no logind.
- **Root filesystem is RAM.** Anything written at runtime is lost on reboot
  unless it is committed or written to the USB drive. This is intentional and
  makes the box hard to corrupt.

### What persists where

| Data | Location | How it persists |
|---|---|---|
| OS config, packages, services | eMMC `apkovl` | `lbu commit` |
| App code (`/opt/rabbitears`) | eMMC `apkovl` | `lbu include /opt/rabbitears` + `lbu commit` |
| Fonts, `mpv.conf` | eMMC `apkovl` | lives under `/etc` or `lbu include` |
| Media library | USB drive | plain files |
| Runtime state (last channel, volume) | USB `/.rabbitears/state.json` | written by the app |
| Schedule index (durations) | USB `/.rabbitears/index.json` | generated by the indexer |

**Rule:** the app never writes to `/` at runtime. State goes to the USB drive,
and if the drive is absent, state is kept in memory only. The one exception is
`/var/log/rabbitears.log` (the supervised process's stdout/stderr), which is
RAM-backed on the diskless box and discarded at reboot — logs only, non-persistent.

### Key packages (initial)
`mpv`, `ffmpeg` (for ffprobe), `python3`, `py3-evdev`, `libva-intel-driver`
(Cherry Trail is Gen8, so use the i965 VA driver and confirm with `vainfo`),
`font-*` or a bundled pixel font, `openssh`, `chrony`, `alsa-utils`.

### Power button
The remote's `KEY_POWER` must **not** shut down the box. Disable or override
Alpine's `acpid`/busybox power-button handler so the event reaches our app,
which treats it as standby.

## 4. Core features (MVP)

### 4.1 Channels
- Each folder in `channels/` on the USB drive is one channel.
- Folder name format: `NN-slug` → channel number `NN`, display name from the
  slug (e.g. `03-magic-school-bus` → **CH 03 · Magic School Bus**).
- Optional `channel.toml` in a folder overrides the display name and order.
- Channel numbers can have gaps (2, 3, 4, 7, 9). Up/down skips missing numbers
  and wraps around.

### 4.2 Clock-based "live" schedule
- Files in a channel are played in a deterministic order: sorted by filename,
  or shuffled with a fixed seed per channel if `shuffle = true`.
- `loop_length` = sum of all file durations (from the index).
- Position = `(now − EPOCH) mod loop_length`, then find which file that falls
  in and the offset within it.
- On tune-in, load that file and seek to the offset. On end-of-file, recompute
  rather than advancing a counter, so drift never builds up.
- `EPOCH` is a fixed constant in config so both boxes air the same schedule.
- Requires correct time: `chrony` with NTP when online, and the hardware clock
  otherwise. A dead CMOS battery will shift the schedule. That's acceptable;
  it should not crash anything.

### 4.3 Playback
- A **single long-running mpv** process, `--vo=gpu --gpu-context=drm`, VAAPI
  hwdec, controlled over the JSON IPC socket.
- Channel changes use `loadfile ... start=<offset>` on the same mpv instance,
  not a process restart.
- Target: **channel change under 1.5s** on the 3040.

### 4.4 Remote controls (MVP)

| Button | evdev | Action |
|---|---|---|
| D-pad ↑ / ↓ | `KEY_UP` / `KEY_DOWN` | Channel up / down; app-side auto-repeat when held |
| OK | `KEY_ENTER` | Toggle info overlay |
| Back | `KEY_BACK` | Dismiss overlay |
| VOL + / − | `KEY_VOLUMEUP` / `KEY_VOLUMEDOWN` | Volume, clamped to a max cap |
| Mute | `KEY_MUTE` | Toggle mute |
| Power | `KEY_POWER` | Standby ↔ on |
| All others | — | Ignored in MVP (reserved, see §9) |

- Input: open every `/dev/input/event*` whose vendor is `0x0627` (scan in
  Python, no udev/by-id dependency), `grab()` them exclusively, and filter by
  code.
- Hot-plug: rescan every few seconds if the dongle disappears.
- **Hold-to-repeat** (channel up/down only): the first repeat fires after
  `repeat_delay` (0.5 s), then every `repeat_interval` (0.4 s) while held.
- **Volume:** each press steps by `volume_step` (5), clamped to `0..volume_cap`
  (80). A volume press unmutes, like a real TV. Volume persists (throttled to
  at most one `state.json` write per 2 s).
- The app is the only actor on a button: the evdev daemon writes one line per
  button to a FIFO, the app maps buttons to a `Command` (`commands.py`) and
  runs it through `App.handle` (§10).

### 4.5 On-screen display
- **Channel flash:** on every tune, show `CH 03` in blocky green
  (`#33CC33`-ish, pixel font, chunky stroke) in the top-right for about 2.5s.
- **Info overlay (OK):** channel number, channel name, current show/episode
  title (from filename), and time remaining.
- Readability over composite on the CRT is the bar: large, all-caps, thick
  border.

### 4.6 Standby
- Power → black screen + mute. mpv keeps running, but video is hidden.
- Waking re-tunes the last channel at the **current** schedule position, so
  time keeps passing while "off," just like real TV.
- While in standby, **only Power has any effect**; every other button is
  ignored.

### 4.7 Failure screens
- **No USB / no channels:** full-screen test pattern with "NO SIGNAL."
  Poll for the drive and recover automatically when it appears.
- **Unplayable file:** log it, skip it, and keep going. Never show an error to
  the viewer.
- **mpv crash:** the service supervisor restarts it, and the app re-tunes.

### 4.8 Boot
Power on → OpenRC starts `rabbitears` → mdev mounts the drive by label
`RABBITEARS` on hotplug and at boot → tune to the last channel from
`state.json`, or the lowest channel if there's no state → channel flash.

## 5. Media rules

- **Container/codec:** MP4, H.264 (High, ≤ L4.1), **720p max**, AAC stereo.
- Avoid 10-bit, HEVC, VP9, and AV1. The 3040 either won't decode them in
  hardware or decodes them unreliably.
- Transcode on the desktop (EVO-X2) with `tools/transcode.sh`, never on the 3040.
- After adding files, run `tools/index.py` on the desktop against the USB drive.
  The box also re-indexes missing entries at boot (slow but safe).
- Filenames become on-screen titles: `Magic School Bus - S01E03 - Gets Eaten.mp4`.

## 7. Development workflow

1. **Develop on the desktop first.** `schedule.py`, `channels.py`, and the mpv
   IPC wrapper all run on the EVO-X2 against `media-example/` with a windowed
   mpv. Most of the logic never needs the 3040.
2. **Deploy to a target** with `uv run task deploy-vm` (VM) or
   `uv run task deploy-box --host H` (box). Deploy streams the repo via tar
   over ssh, runs `setup.sh`, and finishes with `verify.sh`. A `DRIFT` finding
   means someone hand-edited the target: fix the repo and redeploy, never edit
   the box.
3. **Test on the real TV chain** for anything visual: OSD legibility, overscan,
   and audio through the composite converter.
4. **Reproducibility check (each milestone):** wipe Box B, install base Alpine,
   deploy, then compare against Box A. Then do the same using
   only the saved `apkovl`.
5. The saved `apkovl` is **not** committed to git (it contains host keys and
   secrets). Store release copies in a private location, named by date.

  [Pixelarticons](https://pixelarticons.com) is the first choice, tried before

  today and libass renders fonts, not SVGs, so this waits for the first icon
  surface.

- LAN web UI (Flask) for status, manual tuning, and content upload
- Time-of-day programming blocks (mornings differ from evenings)
- Bumps / "Up Next" cards between shows
- Static burst between channel changes
- Station call letters shown in the channel flash
- Sign-off at bedtime (test pattern after a set hour)

  Wyse 5070 chat

## 10. Decisions log

| Date | Decision | Why |
|---|---|---|
| 2026-09 | mpv + small Python app, not Kodi | Kodi's UI is surface area we'd have to fight to lock down |
| 2026-10-04 | Adomax 2.4GHz remote | RF, plug-and-play HID, clean press/release, no repeats |
| 2026-10-14 | Name: **Rabbit Ears** | Nostalgic, kid-friendly |
| 2026-10-14 | Alpine diskless + lbu (not Arch) | Tiny, RAM-root resists corruption, one-file reproducibility |
| 2026-10-14 | Single mpv instance, `loadfile` to tune | Faster channel changes than restarting mpv |
| 2026-10-14 | evdev scan by vendor ID, no udev | One less dependency on Alpine's device manager |
| 2026-10-18 | provision.sh builds / vmctl.py runs | One VM, one build path, one run path; no disk-copy workaround |
| 2026-10-18 | deploy via tar over ssh | No rsync dependency; a fresh box has only the base install |
| 2026-10-18 | VM validates the output path, not VAAPI | virtio-gpu has no VAAPI/i965; hwdec is checked only on the 3040 |
| 2026-10-18 | taskipy tasks as entry points; manifest + verify.sh drift check | Every common action is `uv run task …`; drift is detected, not discovered |
| 2026-10-19 | mdev hotplug mount by label, no fstab entry | One mount path for VM and box; the drive mounts when it appears and lazily unmounts when it goes |
| 2026-10-19 | VM media is an emulated USB stick, not 9p | Exercises the label lookup, mdev rule, exFAT driver, and pull-the-plug behaviour |
| 2026-10-19 | `vm-e2e` is the pipeline's acceptance test | One command proves build → deploy → mount → schedule-correct playback → pull/re-insert → crash recovery; replaces hand-run checklists |
| 2026-10-19 | VM install fails fast with a serial transcript; one QEMU per disk enforced | A silent 30-min hang with no console log made install failures undiagnosable |
| 2026-10-20 | evdev daemon writes button lines to a FIFO; the app is the only actor | One input path (daemon/test double → FIFO → app); the app decides every action, so the remote logic is testable without a physical remote (the VM drives it with a test double) |
| 2026-10-20 | Input sources → `Command` → `App.handle`; sources are swappable | `commands.py` is the one action vocabulary; remote, control socket, and any future source all funnel into `handle`, so the surface stays closed |
| 2026-10-20 | Local root-only control socket for tests/automation; commands + status only, no network | A scripted, read-only probe over SSH (`rabbitears.ctl`); nothing that isn't a `Command` or a read-only `status` |
| 2026-10-20 | Neither the remote nor the ACPI power button shuts the box down | busybox acpid PWRF/PWRB hooks make both a logged no-op; the app's KEY_POWER is standby; recovery from anything is pulling the plug |
| 2026-10-20 | QEMU `usb-kbd` (vendor 0x0627) stands in for the remote in the VM | The app's real vendor scan finds it with no VM branch |
| 2026-10-20 | OSD is mpv `show-text` with ASS override tags, not a separate overlay | One renderer, no second window/compositor; the flash and overlay are just styled text over the video |
| 2026-10-20 | ASS tags are unescaped with the byte `\u0092` + `"a0"`, not the literal `${osd-ass-cc/0}` | mpv 0.41's `show-text` escapes `{…}` by default; the unescape marker is what the `osd-ass-cc/0` property *expands to*, and only that byte sequence turns the tags back on |
| 2026-10-20 | `font-dejavu` for the OSD, not `font-terminus` | terminus is a bitmap font with 12–32 px faces only and renders nothing at the OSD's 72 px; DejaVu is a scalable outline font |
| 2026-10-20 | Flash and overlay are separate `\n` lines in one `show-text` payload | ASS anchors (`\an`) position *lines*, not inline spans, so the top-right flash and the centred overlay can't share a line |
| 2026-10-20 | `e2e-remote` sends a press *and* a release (a tap) for every button | The app's `KeyRepeater` repeats a held channel key until its release arrives; a bare press repeats forever and re-tunes every 0.4 s, corrupting later e2e checks |
| 2026-10-20 | Channel flash fires on *arrivals* only (initial tune, zap, standby wake), not same-channel rollovers (EOF / unplayable skip) | A `CH NN` pop at every episode boundary is the noise §9's "Up Next" cards were deferred to avoid; rollovers still refresh an open overlay's title/remaining |
| 2026-10-20 | Bundled `VCR OSD Mono` is the OSD face (supersedes `font-dejavu`, which stays as the fallback) | A VCR/CRT-style monospace that matches the "cable box" look and scales at 72 px (unlike bitmap `font-terminus`); DejaVu covers glyphs VCR OSD Mono lacks |
| 2026-10-21 | Real dongle passthrough via a provisioned udev rule (`plugdev`) + `vmctl.py run --remote-usb` | QEMU runs as the unprivileged desktop user and the stock USB node is `root:root 0664`, so `usb-host` silently defers; a repo-owned rule installed by `provision.sh` grants durable access without a hand-typed host edit |
